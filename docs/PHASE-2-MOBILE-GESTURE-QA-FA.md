# گزارش QA موبایل و Gestureهای Page-Turn Reader

## دامنهٔ آزمون

آزمون روی branch `feat/comprehensive-mengto-skills-ui` و preview محلی Vite انجام شد. برای مستقل‌کردن آزمون از در دسترس‌بودن backend، یک fixture موقت سه‌اسلایدی در سطح browser fetch شد. ساختار fixture همان قرارداد واقعی پروژه را حفظ کرد: مقاله از مسیر public article و اسلایدها از مسیر article slides خوانده شدند.

به‌دلیل محدودیت محیط مرورگر فعلی، viewport قابل‌تغییر به یک دستگاه واقعی یا شبیه‌ساز ۳۹۰ پیکسلی در دسترس نبود. بنابراین gestureها به‌صورت pointer event با `pointerType: touch` روی سطح reader اجرا شدند و رندر، متن و counter از DOM و screenshot بررسی شد. این آزمون جایگزین تست نهایی روی Safari iOS و Chrome Android نیست، اما مسیر event و state transition واقعی React را بررسی می‌کند.

## سناریوها و نتیجه

| سناریو | انتظار | نتیجه |
|---|---|---|
| ورود به مقالهٔ سه‌اسلایدی | نمایش `1 / 3` و محتوای برگ اول | موفق |
| swipe افقی چپ با فاصلهٔ حدود ۱۴۰ پیکسل | رفتن از اسلاید اول به دوم | موفق؛ counter به `2 / 3` رسید |
| swipe افقی راست | بازگشت به اسلاید قبلی | موفق؛ counter به `1 / 3` برگشت |
| حرکت کوتاه حدود ۲۰ پیکسل | هیچ تغییر اسلایدی رخ ندهد | موفق؛ counter ثابت ماند |
| حرکت عمدتاً عمودی | با page scroll تداخل نکند | منطق gesture به‌دلیل نسبت افقی/عمودی آن را رد می‌کند |
| سه swipe چپ پشت‌سرهم با فاصلهٔ کوتاه | حرکت به `3 / 3`، بدون عبور از انتها | پس از اصلاح state به‌صورت functional موفق؛ نتایج `2 / 3`، سپس `3 / 3` و در swipe مرزی همچنان `3 / 3` بود |
| خروج از ابتدای reader | counter کمتر از `1` نشود | با guard قبلی/functional state محدود می‌شود |
| دادهٔ موقت یا hot reload با index نامعتبر | نمایش `4 / 3` یا صفحهٔ خالی رخ ندهد | با clamp دفاعی جدید index به آخرین اسلاید معتبر محدود شد |
| keyboard و دکمه‌های قبلی/بعدی | مسیر جایگزین gesture فعال بماند | در preview موجود و قابل مشاهده بود |

## نقص شناسایی‌شده و اصلاح

در اجرای اولیه، چند swipe سریع در یک tick می‌توانست به دلیل وابستگی transition به closure قدیمی، وضعیت نامعتبر تولید کند؛ در preview حالت `4 / 3` مشاهده شد. اصلاح انجام‌شده شامل استفاده از functional state update برای `goToNextSlide` و `goToPrevSlide` و اضافه‌کردن clamp دفاعی هنگام تغییر دادهٔ مقاله بود. پس از اصلاح، همان سناریو به `2 / 3`، `3 / 3` و `3 / 3` ختم شد.

Gesture جدید با `PointerEvent` پیاده‌سازی شده است. آستانهٔ حرکت افقی ۴۸ پیکسل است و حرکت فقط زمانی معتبر است که مؤلفهٔ افقی حداقل ۱۵ درصد از مؤلفهٔ عمودی بزرگ‌تر باشد. کلاس `touch-pan-y` امکان scroll عمودی طبیعی را حفظ می‌کند. پس از swipe معتبر، click بعدی suppress می‌شود تا یک gesture به‌اشتباه دو بار page-turn نکند.

## اعتبارسنجی فنی

Lint فایل `ArticleSlides.tsx` بدون خطا و warning موفق است. Production build نیز موفق شد و prerender SEO پروژه بدون خطا اجرا شد. هشدار chunkهای بزرگ، مربوط به baseline موجود پروژه است و از تغییر gesture ناشی نشده است.

## تست‌های باقی‌مانده روی دستگاه واقعی

تست نهایی باید روی iOS Safari و Android Chrome با انگشت واقعی تکرار شود. در این مرحله باید safe-area پایین صفحه، چرخش دستگاه، overscroll، طولانی‌فشردن، دو انگشتی‌بودن gesture، نویز scroll عمودی و عملکرد در اسلایدهای markdown بلند بررسی شود. همچنین RTL فارسی و LTR انگلیسی باید در هر دو جهت swipe به‌صورت جداگانه تأیید شوند.
