# یافته‌های اتصال SMS.ir برای OTP

منبع رسمی: https://sms.ir/rest-api/

SMS.ir برای ارسال کد اعتبارسنجی از متد `POST https://api.sms.ir/v1/send/verify` استفاده می‌کند. هدر احراز هویت `X-API-KEY` است و بدنهٔ درخواست شامل `mobile`، `templateId` و آرایهٔ `parameters` با زوج‌های `name` و `value` است. نمونهٔ رسمی:

```json
{
  "mobile": "919xxxx904",
  "templateId": 123456,
  "parameters": [{"name": "Code", "value": "12345"}]
}
```

پاسخ موفق ساختار `status`، `message` و `data` دارد و در `data` شناسهٔ پیامک و هزینهٔ ارسال برمی‌گردد. کدهای HTTP مستندشده شامل 200 برای موفقیت، 400 برای خطای منطقی، 401 برای احراز ناموفق، 429 برای تعداد درخواست غیرمجاز و 500 برای خطای غیرمنتظره هستند.

منبع رسمی OTP: https://sms.ir/feature/پیامک-otp/

برای سایت کدنویسی‌شده، مستندات SMS.ir استفاده از متد Verify و ایجاد قالب از بخش برنامه‌نویسان/ارسال سریع را توصیه می‌کند. بنابراین `SMSIR_API_KEY` و `SMSIR_TEMPLATE_ID` فقط در backend/Liara قرار می‌گیرند و هرگز به frontend یا Git commit نمی‌شوند.

تصمیم معماری: backend یک کد تصادفی را با hash در PostgreSQL ذخیره می‌کند؛ کد خام فقط به SMS.ir ارسال می‌شود. اعتبار کد کوتاه‌مدت، مصرف یک‌باره و تلاش‌های محدود خواهد بود. قبل از ارسال مجدد، محدودیت بر اساس شماره و IP اعمال می‌شود.
