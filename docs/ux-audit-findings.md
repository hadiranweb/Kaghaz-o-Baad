# یافته‌های اولیه ممیزی UI/UX

تاریخ بررسی: ۲۰ اوت ۲۰۲۶

## وضعیت مشاهده‌شده در سایت زنده

- عنوان صفحه: «کاغذ و باد | پلتفرم نشر آکادمیک».
- سایت در بارگذاری اول یک صفحه تقریباً خالی نشان داد، اما پس از پایدارشدن رندر، هدر و فوتر قابل مشاهده شدند؛ این موضوع احتمالاً نشان‌دهندهٔ ریسک perceived performance یا فاصلهٔ زیاد بین shell و محتوای اصلی است.
- هدر شامل برند «کاغذ و باد»، خانه، منوی محتوا، پخش زنده، منوی درباره، تغییر تم، لینک/آیکون خواندن و ورود است.
- مرکز صفحه یک تصویر مغز کارتونی و یک نوار جست‌وجو با placeholder «جستجو در مقالات...» دارد؛ در viewport بررسی‌شده، این جست‌وجو عملاً مهم‌ترین affordance محتوایی صفحه است.
- فوتر شامل تغییر زبان، لینک‌های شرح پروژه و درباره ما و copyright است.
- پس‌زمینهٔ اصلی سرمه‌ای تیره است و تصویر مغز با رنگ‌های صورتی نقطهٔ کانونی صفحه محسوب می‌شود.
- عناصر تعاملی در نمایش مرورگر annotationهای متعددی گرفتند؛ این برای بررسی دسترسی مفید است، اما باید focus state و کنتراست در حالت واقعی keyboard نیز آزموده شوند.

## نکات اولیه برای پیگیری

1. باید زمان و محتوای لود اولیه، route fallback و احتمال blank state بررسی شود.
2. hierarchy صفحهٔ خانه باید روشن کند محصول چیست و کاربر بعد از جست‌وجو یا ورود چه کاری می‌تواند انجام دهد؛ در حالت فعلی، value proposition و CTA اصلی در viewport مشاهده‌شده برجسته نیست.
3. جست‌وجو باید حالت empty، loading، خطا، نتایج و keyboard shortcut/submit روشن داشته باشد.
4. هدر دسکتاپ متراکم است و چند منوی dropdown/آیکون در کنار هم دارد؛ برای موبایل و زبان انگلیسی باید navigation ساده و قابل پیش‌بینی طراحی شود.
5. تصویر مغز به‌عنوان asset هویتی جذاب است، اما باید با عنوان/متن توضیحی و اقدام واضح همراه شود تا صرفاً تزئینی نماند.
6. رنگ‌های تیره، صورتی و آبی باید از نظر contrast، مخصوصاً placeholder، متن فوتر و focus ring، با WCAG آزموده شوند.

## یافته‌های منابع مرجع

### Sylva
صفحهٔ پروژهٔ Sylva توضیح می‌دهد که صحنهٔ WebGL و رابط HTML/CSS از هم تفکیک شده‌اند، انیمیشن‌ها یک animation loop مشترک دارند و تجربهٔ اصلی بدون درخواست شبکهٔ خارجی بعد از load اجرا می‌شود. برای کاغذ و باد، ارزش قابل اقتباس بیشتر در **تفکیک لایهٔ روایت بصری از HTML قابل استفاده**، staged reveal محدود و navigation واضح است؛ خود WebGL procedural به‌دلیل هزینه و ریسک، انتخاب پیش‌فرض مناسبی برای خانه نیست.

### Complete Shelf
Complete Shelf یک مدل مناسب برای آرشیو/مجموعهٔ مقاله ارائه می‌کند: shelf پیوسته با wheel، کلیدهای arrow، دکمه و position marker؛ interactionهای چندگانه برای orbit/pan/zoom، بازکردن، drag-to-turn؛ و مهم‌تر از همه **کنترل‌های HTML دسترس‌پذیر و status announcement روی صحنهٔ WebGL**. برای پروژه، بخش قابل‌استفاده این الگو، state machine و چند مسیر interaction است، نه کپی صحنهٔ سنگین سه‌بعدی. در صفحهٔ مقاله باید حالت سریع و سادهٔ کارت/لیست همیشه جایگزین viewer تعاملی باشد.

### تصمیم طراحی
- **Reuse/adapt:** منطق state machine برای حالت‌های فهرست مقاله → preview → مطالعه، position marker، next/previous و status announcement.
- **Rewrite for current stack:** رفتارهای page-turn و shelf به‌صورت DOM/CSS/SVG یا viewer سبک در React بازنویسی شوند؛ کد Three.js مستقیم بدون audit مجوز، performance و نیاز واقعی وارد محصول نشود.
- **Reject by default:** افکت‌های دائمی، WebGL تمام‌صفحه، scroll hijacking و audio خودکار؛ چون ارزش محتوایی قطعی ندارند و می‌توانند خوانایی، SEO، battery و accessibility را کاهش دهند.

## ممیزی مسیر مقالات

- مسیر `/read` ابتدا spinner نشان می‌دهد و سپس به empty state «هنوز مقاله‌ای در این دسته وجود ندارد» می‌رسد.
- صفحه عنوان و توضیح دارد، اما در حالت بدون داده اقدام بعدی مشخصی مانند بازگشت به خانه، پاک‌کردن فیلتر، عضویت برای اطلاع از انتشار یا مشاهدهٔ نمونهٔ مقاله ندارد.
- عبارت «نمایش اسلایدی» در توضیح، انتظار interaction خاص ایجاد می‌کند؛ بهتر است کنار آن یک preview کوتاه یا CTA «مشاهدهٔ نمونه» وجود داشته باشد.
- برای صفحهٔ آرشیو، تفاوت بین loading واقعی، خطای API و نبود مقاله باید با سه state مستقل و قابل فهم نمایش داده شود.
