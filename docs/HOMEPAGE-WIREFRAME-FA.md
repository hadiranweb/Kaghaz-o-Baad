# وایرفریم متنی صفحهٔ اصلی «کاغذ و باد»

**هدف صفحه:** در چند ثانیه توضیح دهد «کاغذ و باد» چیست، چه محتوایی ارائه می‌کند و کاربر از کجا باید شروع کند.

**اصل طراحی:** صفحه باید با HTML و CSS ساده کاملاً قابل استفاده باشد؛ انیمیشن باد، ذرات کاغذ یا parallax فقط به‌عنوان لایهٔ تکمیلی اجرا شوند و نباید مسیر اصلی را پنهان کنند.

## ۲. جزئیات بخش‌ها

### Header

هدر باید سبک، ثابت و قابل پیش‌بینی باشد. در دسکتاپ، «مقالات» و «پخش زنده» به‌عنوان مسیرهای اصلی مستقیماً قابل مشاهده باشند. «درباره» می‌تواند منوی ثانویه‌ای شامل «درباره ما»، «شرح پروژه» و «جامعه» باشد.

در موبایل، هدر فقط شامل لوگو، جست‌وجو و منوی بازشونده باشد. منوی موبایل باید ترتیب زیر را داشته باشد:

```text
خانه
مقالات
پخش زنده
شرح پروژه
درباره ما
────────────
زبان: فارسی / English
تم: تیره / روشن
ورود یا داشبورد
```

دکمه‌های icon-only مانند تم، جست‌وجو و منو باید label قابل‌خواندن برای screen reader داشته باشند.

### Hero

Hero باید در اولین viewport کامل یا تقریباً کامل دیده شود. ترتیب پیشنهادی در دسکتاپ، تصویر در یک سمت و پیام/CTA در سمت دیگر است. در RTL، متن در سمت راست و تصویر در سمت چپ قرار گیرد؛ در موبایل، تیتر و CTA پیش از تصویر بیایند تا کاربر سریع‌تر مسیر خود را پیدا کند.

**متن نمونه:**

```text
دانش را بنویس، به اشتراک بگذار و دوباره به گفت‌وگو برگردان.

کاغذ و باد، فضای نشر آکادمیک دوزبانه برای مقاله، نمایش اسلایدی
و گفت‌وگوی زنده است.
```

**اقدام‌ها:**

```text
دکمهٔ اصلی: مشاهدهٔ مقالات
دکمهٔ ثانویه: آشنایی با پروژه
```

جست‌وجو باید label مستقلی مانند «در مقالات جست‌وجو کنید» داشته باشد. پیشنهادهای جست‌وجو در یک listbox زیر input نمایش داده شوند و با کلیدهای بالا/پایین، Enter و Escape قابل کنترل باشند.

### سه مسیر اصلی

این بخش باید کاربر را از صفحهٔ عمومی به سه تجربهٔ اصلی هدایت کند. کارت‌ها بهتر است از نظر ساختار یکسان باشند: عنوان، توضیح یک‌جمله‌ای، metadata کوتاه و یک CTA. از آیکون یا illustration برای تقویت معنا استفاده شود، نه برای جایگزین‌کردن متن.

| مسیر | وعدهٔ تجربه | CTA |
|---|---|---|
| مقالات | کشف و مطالعهٔ مقاله‌های آکادمیک دوزبانه | مشاهدهٔ مقالات |
| نمایش اسلایدی | مرور ایده‌ها به‌صورت فصل‌به‌فصل و سریع | مشاهدهٔ نمونه |
| پخش زنده | پیوستن به گفت‌وگو، پرسش و جمع‌بندی | مشاهدهٔ جلسات |

### مقالهٔ منتخب

در صورت نبود مقالهٔ منتشرشده، این بخش نباید خالی بماند. به‌جای آن یک empty state کنترل‌شده نمایش دهید:

```text
اولین مقاله‌ها به‌زودی منتشر می‌شوند.
در این فاصله با ایدهٔ کاغذ و باد و شیوهٔ انتشار آشنا شوید.

[شرح پروژه]  [بازگشت به جست‌وجو]
```

در صورت وجود مقاله، کارت منتخب شامل عنوان، چکیدهٔ کوتاه، نویسنده، تاریخ، زمان مطالعه و دو مسیر «خواندن مقاله» و «مشاهدهٔ اسلایدها» باشد.

### چگونه کار می‌کند؟

این بخش باید محصول را بدون اصطلاحات فنی توضیح دهد. متن کوتاه پیشنهادی:

```text
۱. بنویس
ایده، مقاله یا نتیجهٔ پژوهش خود را آماده کن.

۲. آماده کن
روایت، اسلاید و زمینهٔ لازم را برای خواننده بساز.

۳. رها کن
دانش را منتشر کن و آن را به گفت‌وگویی قابل ادامه تبدیل کن.
```

### اصول انتشار

این بخش برای اعتمادسازی مهم است، به‌خصوص چون محصول ماهیت آکادمیک دارد. هر اصل با یک توضیح کوتاه ارائه شود:

```text
شفافیت       مشخص‌بودن وضعیت و نسخهٔ محتوا
ارجاع‌پذیری   حفظ منابع و زمینهٔ علمی
گفت‌وگو       امکان پرسش و بازخورد
بازبینی       اصلاح و تکمیل محتوا پس از انتشار
```

### CTA پایانی

CTA پایانی باید با توجه به وضعیت کاربر تغییر کند. برای کاربر ناشناس، «مشاهدهٔ مقالات» و «شرح پروژه» مناسب است. برای کاربر واردشده، می‌توان «رفتن به داشبورد» را به‌عنوان اقدام ثانویه نشان داد.

## ۳. نسخهٔ responsive

### دسکتاپ

Hero به‌صورت دو ستونه اجرا شود؛ عرض متن محدود و CTAها در یک ردیف قرار گیرند. سه مسیر اصلی در یک ردیف سه‌تایی و مقالهٔ منتخب در layout دو ستونه نمایش داده شود.

### تبلت

Hero همچنان دو ستونه اما فشرده‌تر باشد. سه مسیر اصلی می‌توانند در یک ردیف اسکرول افقی کنترل‌شده یا دو ردیف قرار گیرند؛ از carousel خودکار پرهیز شود.

### موبایل

ترتیب محتوا باید چنین باشد: تیتر، توضیح، CTA اصلی، جست‌وجو، تصویر، سه مسیر اصلی، مقالهٔ منتخب و CTA پایانی. کارت‌ها تمام‌عرض باشند و دکمه‌ها حداقل فضای لمسی مناسب داشته باشند. هیچ تعامل مهمی نباید فقط به hover وابسته باشد.

---

## ۴. motion و fallback

نسخهٔ پایه باید بدون motion کامل باشد. در حالت عادی می‌توان از حرکت بسیار نرم تصویر hero، reveal مرحله‌ای کارت‌ها و texture ظریف کاغذ استفاده کرد. در `prefers-reduced-motion: reduce` همهٔ این عناصر به حالت ثابت تبدیل شوند.

```text
Normal motion:      تصویر ثابت + parallax بسیار محدود + reveal کوتاه
Reduced motion:     تصویر ثابت + بدون parallax + بدون particle
No JavaScript:      تیتر، متن، لینک‌ها و فرم جست‌وجوی استاندارد
Mobile ضعیف:        حذف particle و کاهش blur و shadow
```

## ۵. معیار پذیرش وایرفریم

| معیار | وضعیت مطلوب |
|---|---|
| فهم محصول | کاربر در اولین viewport بداند محصول چیست و چه چیزی ارائه می‌کند. |
| شروع مسیر | حداقل یک CTA واضح برای مقالات و یک CTA برای آشنایی با پروژه وجود داشته باشد. |
| جست‌وجو | input دارای label، loading، خطا، empty state و keyboard interaction باشد. |
| دوزبانگی | نسخهٔ فارسی و انگلیسی از نظر hierarchy و عملکرد هم‌ارز باشند. |
| دسترس‌پذیری | مسیر اصلی با keyboard و screen reader قابل استفاده باشد. |
| responsive | hero و CTAها در موبایل بدون scroll افقی یا شکست layout قابل مشاهده باشند. |
| performance | محتوای اصلی پیش از animation قابل مشاهده شود. |
| fallback | نبود JavaScript، reduced motion و دستگاه ضعیف مانع استفاده از سایت نشود. |
