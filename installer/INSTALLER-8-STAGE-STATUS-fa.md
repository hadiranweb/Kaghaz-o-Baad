# گزارش وضعیت هشت‌مرحله‌ای installer کاغذ و باد

## مدل نهایی مورد توافق

installer یک **EXE خودبسنده** است که همراه repository در اختیار کاربر قرار می‌گیرد. کاربر نباید repository یا ZIP را داخل رابط انتخاب کند. EXE مسیر repository والد خود را تشخیص می‌دهد، نوع مقصد را می‌پرسد، تنظیمات لازم را دریافت می‌کند، پیش‌نمایش امن نشان می‌دهد و پس از تأیید، یک کپی جدید و آمادهٔ انتقال در workspace خروجی می‌سازد.

installer هیچ deployment، upload، migration، seed، اتصال database، DNS، SSL، پرداخت یا تغییر مستقیم زیرساختی انجام نمی‌دهد.

## چه چیزهایی اکنون انجام شده است؟

ساخت EXE ویندوزی با `electron-builder` و NSIS موفق شده است. همچنین `npm run check` و `npm run build` پس از تغییر معماری موفق هستند. رابط installer دیگر ورودی repository یا ZIP را از کاربر مطالبه نمی‌کند؛ مسیر repository از محل EXE تشخیص داده می‌شود.

جریان preview و تأیید نهایی نیز اضافه شده است. secretها در preview کامل نمایش داده نمی‌شوند و پس از تأیید، در کپی محلی خروجی در فایل‌های server-side نوشته می‌شوند. installer هیچ عملیات خارجی یا زیرساختی انجام نمی‌دهد.

## مواردی که هنوز نباید انجام‌شده تلقی شوند

وجود فرم برای یک integration به‌تنهایی به معنی فعال‌بودن آن integration در backend نیست. متغیرهای AI، SMS، پرداخت، Mail، LiveKit و Object Storage باید در مرحلهٔ بعد با adapter یا سرویس واقعی خودشان تطبیق داده شوند. installer فقط مقداردهی configuration را انجام می‌دهد و منطق آن سرویس‌ها را ایجاد نمی‌کند.

همچنین آزمون ساخت EXE در Linux انجام شده است، اما آزمون واقعی بازکردن رابط، تشخیص مسیر repository، انتخاب پوشهٔ خروجی و نوشتن فایل‌ها باید روی Windows انجام شود.

## ترتیب صحیح کارهای باقی‌مانده

ابتدا باید runtime EXE روی Windows آزمایش شود. سپس باید validation workspace و invalidation preview تکمیل شود. بعد از آن، نقاط configuration رسمی backend و frontend باید به templateهای مشخص تبدیل شوند تا installer از تغییر کورکورانه یا نوشتن متغیر بلااستفاده جلوگیری کند. در مرحلهٔ بعد گزارش diff و checksum اضافه می‌شود. در پایان، دو سناریوی Liara و Single Server با repository کپی‌شده و تنظیمات ساختگی آزمایش می‌شوند؛ بدون آنکه installer واقعاً به Liara یا سرور متصل شود.

## فایل اجرایی فعلی

`release/KaghazBaad-Installer-0.1.0.exe`

این فایل باید همراه repository یا در محل مورد توافق داخل آن قرار گیرد. installer فقط زمانی می‌تواند repository را خودکار پیدا کند که در ریشهٔ repository یا یکی از زیرپوشه‌های آن قرار داشته باشد.
