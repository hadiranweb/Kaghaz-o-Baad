# قرارداد installer کاغذ و باد

این ابزار installer ویندوزی کاغذ و باد است، نه خودِ محصول و نه جایگزین backend. خروجی رسمی آن یک فایل EXE است که فقط repository را برای مقصد انتخاب‌شده مقداردهی و در یک workspace جدید کپی می‌کند.

## قواعد غیرقابل‌مذاکره

1. EXE همراه repository منتشر می‌شود و ریشهٔ repository را از محل اجرای خودش به‌صورت خودکار تشخیص می‌دهد. کاربر repository یا ZIP دیگری انتخاب نمی‌کند. installer پس از دریافت تنظیمات تعاملی مجاز است مقادیر لازم مانند `DATABASE_URL`، JWT secret، کلید AI، کلید SMS، کلید درگاه، token LiveKit و سایر token/APIها را در کپی محلی مقصد بنویسد.
2. installer همیشه یک کپی جدید از repository در workspace انتخابی می‌سازد و به فایل منبع اصلی دست نمی‌زند.
3. installer قبل از کپی نهایی، نوع مقصد، مسیر خودکار repository، مسیر خروجی، فهرست فایل‌های تغییرکرده و مقادیر تنظیمی را به‌صورت امن و قابل‌خواندن نشان می‌دهد و تأیید صریح می‌گیرد.
4. دو مسیر رسمی وجود دارد: «همه‌چیز روی یک سرور» و «زیرساخت Liara». مسیر Liara شامل PaaS برای frontend/backend، DBaaS برای PostgreSQL، Object Storage، DNS/SSL و در صورت نیاز سرور جدا برای LiveKit است.
5. secretها و tokenها فقط در کپی محلیِ خروجی و در فایل‌های server-side یا پیکربندی رسمی پروژه نوشته می‌شوند. secret کامل در log یا گزارش عمومی چاپ نمی‌شود؛ رابط فقط وجود، نام متغیر و در صورت نیاز مقدار قابل‌مشاهدهٔ مورد تأیید کاربر را نشان می‌دهد.
6. installer هیچ‌وقت روی repository ورودی overwrite نمی‌کند، به Git push/reset/delete انجام نمی‌دهد و هیچ deployment، upload، migration، DNS، SSL، پرداخت یا عملیات زیرساختی اجرا نمی‌کند.
7. installer به پایگاه‌داده متصل نمی‌شود، schema را بررسی نمی‌کند و migration یا seed اجرا نمی‌کند؛ فقط متغیرها و فایل‌های لازم را برای اجرای این مراحل توسط کاربر در مقصد آماده می‌سازد.
8. installer فقط فایل‌های تنظیمات و مسیرهای رسمی پروژه را تغییر می‌دهد. جایگزینی کورکورانهٔ رشته‌ها در همهٔ فایل‌ها ممنوع است.
9. اگر پیش‌نیازی مانند Liara DBaaS، دامنه، Object Storage یا secret ناقص باشد، installer متوقف می‌شود و راهنمای دقیق می‌دهد؛ مقدار ساختگی تولید نمی‌کند.
10. installer فقط یک کپی نهایی از کد و تنظیمات آمادهٔ انتقال ایجاد می‌کند. پس از ساخت پوشهٔ خروجی، کاربر خودش فایل‌ها را به Liara یا سرور منتقل می‌کند و مراحل نهایی استقرار را انجام می‌دهد.
11. installer باید تنظیمات را فقط در فایل‌ها و نقاط کنترل رسمی پروژه بنویسد. secretها نباید در bundle عمومی frontend، log، Git یا repository ورودی نوشته شوند؛ کپی خروجی محلی متعلق به کاربر است و باید با دسترسی مناسب نگهداری شود.
12. EXE باید روی Windows اجرا شود، repository والد خود را خودکار تشخیص دهد، نوع مقصد و workspace خروجی را از کاربر بگیرد، در صورت تأیید کاربر کپی خروجی جدید بسازد و گزارش تغییرات و مسیر خروجی را ارائه کند. دریافت ZIP یا انتخاب repository ورودی خارج از قرارداد نهایی است.

## وضعیت‌های گزارش

هر مرحله باید یکی از این وضعیت‌ها را داشته باشد: `not_started`، `validated`، `generated`، `applied`، `verified` یا `blocked`.

هیچ مرحله‌ای با وجود صرفاً یک فایل یا template «انجام‌شده» محسوب نمی‌شود؛ باید نتیجه، خطا، فایل‌های تغییرکرده و امکان rollback ثبت شود.
