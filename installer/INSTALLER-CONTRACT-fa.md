# قرارداد installer کاغذ و باد

این installer ابزار آماده‌سازی استقرار کاغذ و باد است، نه خودِ محصول و نه جایگزین backend.

## قواعد غیرقابل‌مذاکره

1. فایل ZIP عمومی شامل کد و فایل‌های نمونه است، اما هرگز شامل `DATABASE_URL`، رمز عبور، JWT secret، کلید AI، کلید SMS، کلید درگاه، token LiveKit یا هر secret واقعی نیست.
2. installer همیشه یک کپی جدید از repository در workspace انتخابی می‌سازد و به فایل منبع اصلی دست نمی‌زند.
3. installer قبل از هر عملیات حساس، مسیر مقصد، نوع deployment و فهرست اقدام‌ها را نشان می‌دهد و تأیید صریح می‌گیرد.
4. دو مسیر رسمی وجود دارد: «همه‌چیز روی یک سرور» و «زیرساخت Liara». مسیر Liara شامل PaaS برای frontend/backend، DBaaS برای PostgreSQL، Object Storage، DNS/SSL و در صورت نیاز سرور جدا برای LiveKit است.
5. secretها فقط در فایل‌های محلی خارج از repository یا در تنظیمات server-side مقصد نوشته می‌شوند. secret در log، manifest عمومی، خروجی UI یا commit قرار نمی‌گیرد.
6. installer هیچ‌وقت `main` یا branch منبع را push، reset یا حذف نمی‌کند و هیچ migration production را بدون تأیید محیط مقصد اجرا نمی‌کند.
7. عملیات دیتابیس ابتدا با اتصال و بررسی schema آغاز می‌شود و migrationها با runner دارای checksum و transaction اجرا می‌شوند.
8. installer فقط فایل‌های تنظیمات و مسیرهای رسمی پروژه را تغییر می‌دهد. جایگزینی کورکورانهٔ رشته‌ها در همهٔ فایل‌ها ممنوع است.
9. اگر پیش‌نیازی مانند Liara DBaaS، دامنه، Object Storage یا secret ناقص باشد، installer متوقف می‌شود و راهنمای دقیق می‌دهد؛ مقدار ساختگی تولید نمی‌کند.
10. deployment واقعی از نصب‌کننده جداست: نسخهٔ اول installer می‌تواند workspace و پیکربندی آماده تولید کند؛ اجرای استقرار فقط پس از تأیید کاربر انجام می‌شود.

## وضعیت‌های گزارش

هر مرحله باید یکی از این وضعیت‌ها را داشته باشد: `not_started`، `validated`، `generated`، `applied`، `verified` یا `blocked`.

هیچ مرحله‌ای با وجود صرفاً یک فایل یا template «انجام‌شده» محسوب نمی‌شود؛ باید نتیجه، خطا، فایل‌های تغییرکرده و امکان rollback ثبت شود.
